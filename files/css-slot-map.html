CSS: a slot map

The CSS standard is not a list of documents. It is a fixed set of questions asked in a fixed order, and each module is the current answer to one of them. Learn the questions and the documents stop mattering.

The one idea

CSS2.1 was one document with a table of contents. Everything since is that table of contents, broken into pieces that version independently.

A browser has to do seven things with a stylesheet, in order. Decide which rules are active. Find the elements each rule hits. Resolve conflicts into one value per property per element. Build boxes. Position and size them. Paint them. Change them over time. That sequence has not moved since 1998 and will not move.

Every CSS module answers a question inside one of those seven stages, or it defines the substrate all seven share. Nothing else exists. When a new module appears, you do not learn a new structure — you ask which stage's question it answers and drop it in.

This is why the W3C page you were reading is disorienting. It sorts by how confident the Working Group is, not by what each module does. Grid 1 and Grid 2 land in a different section from Flexbox. Selectors 3 is in the official definition and Selectors 4 is two tiers down. None of that is structural.

The map

Five rules that keep it stable

These are the load-bearing parts. If you hold these, a new spec release costs you one line of revision, not a rebuild.

A slot is a question, not a document
“How do I select elements?” is the slot. Selectors 3 was the answer, Selectors 4 is the answer, Selectors 5 will be the answer. The slot never moves, so nothing you learned about it gets invalidated — only the pointer updates.
Levels are per-module and monotonic
There is no CSS4. Each module levels independently, and a higher level is a superset of the lower one with narrower permitted behaviour. So Grid 1 and Grid 2 are one slot, not two. Read the highest published level, and fall back to the lower level only for what the higher one did not touch.
Maturity is an attribute of the answer, never a location
The four sections of the Snapshot are a confidence rating. Treat them as a column in a table, not a branch in a hierarchy. A module moving from “rough interoperability” to “official definition” changes one chip and nothing else.
CSS2.1 is the root of the tree
Every module either replaces a named CSS2.1 chapter or fills a slot CSS2.1 never had. The Snapshot annotates this explicitly, module by module. That gives you a free exhaustiveness check: walk the CSS2.1 table of contents and confirm each chapter has a successor or an explicit gap.
New work arrives in only four shapes
A level bump, a split, a merge, or a genuinely new slot. All four are cheap edits. The last section is the procedure.

0Substrate

What is a stylesheet made of, before any element is involved?

This layer is invisible in day-to-day authoring and load-bearing for everything else. Syntax defines the tokenizer and the forward-compatible error rules — the reason an unknown property is dropped rather than breaking the block. And @supports is the only mechanism CSS has for asking about itself.

2Match

Given an active rule, which elements does it apply to?

Selectors is the whole slot; the rest are extensions to it. Pseudo-elements are worth separating in your head, because they straddle two stages: Selectors defines how you write ::marker, and Pseudo-Elements defines what box it actually generates back in stage 4.

3Cascade

Several rules matched. Which declaration wins, and what value does the property actually end up with?

This is the narrowest stage by document count and the deepest by consequence. One module owns nearly all of it. Its real content is a pipeline inside a pipeline — a value passes through six named states, and most confusion about CSS behaviour is confusion about which state you are looking at.

4Generate boxes

Computed values are settled. What boxes now exist, and from which elements?

The box tree is not the element tree. One element can produce several boxes, or none, or boxes it has no markup for. Display owns that transformation, and it is the stage most authors skip past — which is why display behaving as a shorthand for an outer and an inner value comes as a surprise.

5Lay out

Where does each box sit, and how big is it?

The largest stage, and the one worth splitting in two. Geometry modules define terms and constraints that every layout algorithm shares. Layout modes are the algorithms themselves. Box Alignment is the clearest illustration: justify-content is defined once, in one module, and flex, grid, block, and table layout all consume that single definition.

6Paint

Geometry is settled. What actually gets drawn, and in what order?

The widest stage by module count, and the easiest to navigate, because the modules carve up cleanly by what they draw. One thing to keep straight: Text belongs here rather than in layout, even though line breaking clearly affects geometry. The Working Group split the old CSS2.1 text chapter four ways — Text, Writing Modes, Text Decoration, and Line Grid — and only the first three are live.

7Animate

How does any of the above change over time, and what drives the clock?

The structure here is a single model with several drivers on top. Web Animations defines the timing model; Transitions and Animations are two declarative ways to feed it; Easing supplies the timing-function value type all of them share. Once you see that shape, the scroll modules stop looking like strays — they are alternative clocks.

Cross-cutting frames

These are the modules that break a purely staged model. Each one re-keys several stages at once, which is why filing them under a single stage always feels wrong.

Writing Modes is the sharpest example. It does not add a feature to one stage. It replaces the coordinate system that sizing, alignment, layout, fragmentation, and text all operate in — physical top and left become flow-relative block-start and inline-start. Logical Properties then supplies a flow-relative twin for every physical property CSS already had.

The maturity axis

The Snapshot's four sections, restated as one ordinal attribute you attach to a slot's current answer.

TierWhat it claimsCount
I  Official definitionStable, and with enough implementation experience that the Working Group is sure of that stability. This is what “CSS” formally means in 2026.24
II  Reliable CRStable spec and stable implementations, held back by minor issues or missing implementation reports.8
III  Fairly stableDesign work finished, testing and implementation experience thin.10
IV  Rough interoperabilityWidely shipped, imprecisely specified. Works in the common cases and diverges at the edges.22
—  Not in the SnapshotWorking Draft. May still be safe to use — the Snapshot maintains an explicit list of pre-CR features cleared for broad release, including :has(), aspect-ratio, color-mix(), and env().—

Two things this axis is not. It is not browser support — the Snapshot says outright that its audience is implementers and that inclusion turns on specification stability, not adoption. For support, use caniuse or Web Platform Tests. And it is not a reading order: Tier IV contains Selectors 4, CSSOM, and Web Animations, which you will reach for constantly.

Empty slots and dead ends

A complete map has to show where the road stops. These are the places the modular rewrite never finished, and the branches that were abandoned.

Slots CSS2.1 still owns

  • Normal flow — block and inline layout is still defined by CSS2.1 §9 and §10. No module has replaced it.
  • Tables — CSS2.1 §17. css-tables-3 exists but has not moved.
  • Generated content — CSS2.1 §12. css-content-3 is marked severely outdated.
  • Paint order and stacking — CSS2.1 Appendix E.

Split and merged, so you know which name to search

  • The CSS2.1 text chapter became four modules: Text, Writing Modes, Text Decoration, and Line Grid.
  • Web Fonts was folded into Fonts, and @font-face lives there now.
  • Line Layout was replaced by Inline Layout.
  • Backgrounds and Borders is splitting at Level 4 into Backgrounds 4 and Borders and Box Decorations 4.
  • Fragmentation was assembled from pieces of Paged Media and Multi-column.

Abandoned — do not chase these

Grid Positioning, Grid Template Layout, Regions, Marquee, Presentation Levels, the Reader media type, Hyperlink Presentation, Behavioral Extensions, Fullscreen, and CSS Math. The Mobile, Print, and TV profiles are also discontinued and unmaintained; the Working Group stopped publishing profiles because they were not proving useful.

Updating the map

The procedure, for when a spec moves or a module you have never heard of turns up.

Is it a level bump?
Same slot. Update the pointer to the higher level and note what it added. Nothing else changes. Most releases are this.
Is it a split?
One slot becomes two or three siblings under the same stage. Keep them adjacent — the split usually means a chapter grew large enough to level independently, not that the concepts diverged.
Is it a merge?
Two slots collapse into one. Keep the retired name as a search alias; the old spec title is how the feature is still indexed everywhere else.
Is it a genuinely new slot?
Ask which of the seven questions it answers. Container queries answer “which rules are active”, so they are stage 1. Anchor positioning answers “where does this box sit”, so it is stage 5. View transitions answer “how does this change over time”, so stage 7. If it answers none of them cleanly, it is a cross-cutting frame — and that list is short and grows slowly.

The one case that needs care: a module can legitimately sit in two stages, and forcing it into one loses information. Color Adjustment is a filter and a paint concern. Pseudo-elements are matched in stage 2 and generate boxes in stage 4. Containment scopes boxes in stage 4 and supplies query conditions in stage 1. Note the second home rather than deleting it.
